# AppData Scanner

一个 DeepSeek Harness（DSH）客户端插件：**只读**分析 Windows 的 `AppData` 目录，回答三个问题——

> 这个目录占了多少空间？是哪个软件生成的？能不能删？

**它不会删除任何东西。** 只帮你定位和解释，删除的决定权始终在你自己手里。

## 先读这一条：判断只是参考

**这个插件给你的是「参考资料」，不是「清理指令」。**

三个问题里，**「这是什么、谁生成的、装了些什么」才是它的主业**；「能不能删」只是一个基于目录名、目录内的文件类型和内置知识库推断出来的**参考结论**——它并不知道你的实际情况：这里可能是某款软件的授权文件、可能是你还没导出的工程、也可能是公司软件下发的配置。

所以动手之前，请按这个顺序：

1. **先看「用途」一栏**——它比安全级重要，告诉你这块空间在被谁使用；
2. **拿不准就点行尾的文件夹图标**，在资源管理器里亲眼看一下再决定；
3. **有疑虑就留着**。目录留着只是占点空间，删错可能不可恢复。

**删除由用户自行操作，请对自己的数据负责。**

## 它是怎么判定的

**只扫描目录，不检索文件。**

- 扫描时只统计每个目录的递归体积、文件数、最后修改时间，以及目录里出现了哪些文件类型；**不读取任何文件内容**。
- 判定的对象是**目录**：目录代表这块空间的用途。内置知识库为常见应用目录给出「用途 + 生成它的软件 + 删除后会怎样」，并按可安全删除／需拆分确认／不可删除给出结论。
- 知识库没有覆盖的目录，按名称与内容特征做启发式推测，并明确标注为**推测**——不确定就说不确定。
- 一个目录里混着缓存和用户数据时，例如 `Edge\User Data` 里书签和缓存是邻居，不给整块结论，拆到子项分别判定。
- **0.7.0 起，判定完全以目录为单位**，此前会单独识别个别文件并给出建议。

判定优先级：**知识库匹配 → 混合目录拆分 → 启发式 → 推测**。

## 特性

- **资源管理器式浏览**：点文件夹进入下一层，顶部「← 返回上一级」加面包屑跳级
- **递归体积统计**：显示每个目录含所有后代的真实大小、文件数、最后修改时间
- **三种排序**：名称／大小／修改日期，可切换升降序，选择会记住
- **三档安全判定**：可安全删除／需拆分确认／不可删除，混合目录会拆到子项
- **一键定位**：每行一个按钮，在资源管理器中打开并选中该目录
- **按需联网**：对未知目录可联网检索加模型总结，给出结论与带摘要的来源
- **按需加载**：不点图标不扫描；点开图标后先跑一次扫描，并做一次能力探测

## 安装

### 在 DSH 里安装

侧边栏「插件」→「安装第三方插件」，下面三种输入任选其一。

**① npm 包链接**

```
dsh-appdata-scanner
```

**② GitHub 链接**

```
https://github.com/twoweeks1995/dsh-appdata-scanner
```

**③ 本地文件**

先从 [Releases](https://github.com/twoweeks1995/dsh-appdata-scanner/releases) 下载 tgz，
安装框填它的绝对路径，版本号以 Releases 页为准：

```
D:\temp\dsh-appdata-scanner-0.7.1.tgz
```

安装后**完全退出 DSH 再启动**，左侧栏会出现「AppData Scanner」图标。

详见 [INSTALL.md](./INSTALL.md)。

## 设计原则

**① 只读**
不修改、不创建、不删除被扫描目录下的任何文件；插件里没有任何删除按钮，也不会执行任何删除命令。
命令行版 `plan` 只会**打印**一条回收站删除命令给你自己核对后手动执行。

**② 说明优先于判断**
先讲清这块空间是谁的、装了什么，再谈能不能删。只给「可删／不可删」而不说用途，等于让你盲删。

**③ 语义优先于体积**
先判用途再看大小。按体积排序然后勾大户，第一个就会建议你删掉聊天记录。

**④ 混合目录必须拆分**
一个目录里同时有缓存和用户数据时，不给整块结论，拆到子项分别判定。

**⑤ 不确定就说不确定**
知识库未命中的目录标记为「推测」；联网结论恒为【联网·未证实】；模型提示词里明确要求「只依据来源作答，不足就写信息不足」。

## 已知限制

- **联网查询需要配置 API key**。没有凭据时不会报错，只是把查询串复制到剪贴板，由你自己去问。
- 配好凭据时，**光是打开面板就会产生一次远端检索**，用于探测联网能力，结果缓存 5 分钟。
- 部署里没有 `web` 服务时，插件不会加载，因为该服务在 `inject` 里声明为必需。
- 「在资源管理器中打开」依赖 `explorer.exe`，仅 Windows 可用；扫描与判定本身跨平台。
- 首次打开面板需完整扫描一次，约 18 至 25 秒，才能给出精确体积，之后走缓存。
- 树视图单个目录 5 秒预算、单次请求 20 秒预算；首次全量扫描每个顶层目录 15 秒预算，超大目录会标注「统计中断」。
- **知识库有待进一步完备**：没覆盖到的目录只能给「推测」，这类条目不要当作结论用。
  如果你手上有更完整的资料，可以用 DSH 整理总结后发给维护者，我们会补进知识库。
